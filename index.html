Synexa Multi-Tenant Architecture Guide

How this application scales from a single café to thousands of restaurants and hotel rooms without rewriting code.

1. Tenant Isolation: Every diner request carries a tenant identifier (e.g. ?tenant=olive-kitchen&table=4). The database queries filter by business_id via Supabase Row-Level Security (RLS).
2. Reusable Phase 1 MVP: Restaurant managers upload dishes, set calorie/protein nutrition facts, toggle out-of-stock items, and print table tent cards in seconds.
3. Phase 2 & 3 Expansion: The data model already contains order items, status tracking (KDS), and payment hooks (Razorpay UPI) for a frictionless upgrade.
